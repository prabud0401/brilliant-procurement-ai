## Scope
1. **Documents list** (`/documents`): table with filters (type, status, vendor, suspicious, duplicate, date), search, paging; status badges; role-aware (Requester sees own; Buyer all; Manager department; Admin metadata only — the API already scopes; the UI hides actions the role cannot use).
2. **Upload** (Buyer and Requester per design 7.2): drag-and-drop or file picker, document type select, client-side type/size checks mirroring design 7.4, progress, then **status polling** (queued → processing → needs_review/ready/failed) without page reload; duplicate upload shows the existing document with a link; failed extraction shows the reason and a **Retry** button (`POST /documents/{id}/extract`).
3. **Review split screen** (`/documents/[id]`): left — PDF page viewer with **PDF.js** (`pdfjs-dist`, worker bundled locally, no CDN), page navigation and zoom, a **highlight box** drawn from the selected field's/line's `page` + `bbox`; deep link `?page=n&highlight=<field or chunk id>` for citations (US-20). Right — extracted header fields and line items with **confidence badges** (under 0.80 marked needs review), validation messages, inline **correct** (PATCH field/line with value; show before/after saved), **confirm field/line**, **choose vendor** (from seeded vendors), **clear duplicate** with reason dialog, **suspicious-content banner** (US-29: explains the document contains text that looks like instructions to the AI, which were ignored) with an **Acknowledge** dialog requiring a reason (`POST /documents/{id}/acknowledge-suspicious`), and **Confirm document** (disabled with the list of open items while anything is open; shows the 409 problem details otherwise). Requesters and Managers see the review read-only; Admin sees metadata only.
4. Every action gives a toast and refreshes state in place (no full reload); errors show problem-details messages with the request ID; keyboard accessible (tab order, focus trap in dialogs, visible focus, labels); works at 1280px and is usable at tablet width.
