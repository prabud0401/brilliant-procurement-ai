## Scope
1. `POST /api/v1/intake/email` (multipart: file, sender, subject, received_at, message_id): authenticated ONLY by an API key in header `X-Intake-Key`, compared in constant time against a hash (argon2 or SHA-256 with pepper) stored in settings/env (`INTAKE_KEY_HASH`); the key itself never in the repo, logs or responses. The principal is a dedicated `intake` service account whose only capability is this endpoint — it cannot read, list or change anything else (a token-based call by it to any other endpoint is refused, and the key is refused on any other endpoint).
2. Reuses exactly the upload checks and storage from `app/documents` (type by magic bytes, size, pages, encrypted/corrupt, SHA-256 duplicate → 409); saves `source="email"`, sender, subject, received time and message id on the document (use existing columns `source`, `source_url` / metadata — no migration unless strictly required; if required, add one small migration and say so); audit entry `document.received_by_email` with sender, subject, received time; then enqueues normal extraction. Optional sender allowlist (setting `intake_sender_allowlist`, empty = allow all) and a per-sender rate limit.
3. A CLI `python -m app.intake.keygen` that prints a new random key once and its hash (for Key Vault / settings), never storing the plain key.
4. `infra/logicapp/logicapp.bicep` (Consumption): Outlook.com connection (`Microsoft.Web/connections`, api `outlook`; the one-time sign-in is a manual step), trigger "When a new email arrives (V2)" with attachments only, polling every 5 minutes; for each attachment with allowed content type (PDF, PNG, JPEG) and size ≤ limit, HTTP POST to the API with the key from a `@secure()` parameter; secure inputs/outputs on the HTTP action; `enabled` parameter. Wired from `infra/main.bicep` behind `enableEmailIntake` (default false). README section with the manual sign-in step and the teardown note.
