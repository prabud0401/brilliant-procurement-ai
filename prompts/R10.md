## Scope
1. **Q&A screen** (`/qa`): chat-style question box with history in the session; answers rendered as text with numbered **citations** (document name, page) that open the document review page at that page with the highlight (`/documents/{id}?page=n&highlight=<chunk id>`); a clear **refusal** message when the API refuses (no answer in the user's documents); loading/empty/error states; roles per design 7.2 (Admin has no Q&A).
2. **Telemetry**: OpenTelemetry in api, worker and web using the Azure Monitor OpenTelemetry distro when `APPLICATIONINSIGHTS_CONNECTION_STRING` is set, and a no-op (or console in dev when `OTEL_DEBUG=1`) otherwise — never a hard dependency at runtime and no network in tests. Add the env var name to Settings.
3. **Correlation ID end to end**: the `X-Request-ID` from web → api is stored on enqueued jobs (payload) and re-used by the worker's logs and the audit entries the worker writes (`request_id` column), so one upload can be traced by a single ID across web, api, worker and audit_log.
4. **AI metric events** per AI call (task, model, prompt version, latency, tokens in/out, estimated cost, refusal flag, injection flag) emitted as custom events/log records through one helper, hooked where `app/ai` already meters calls (minimal edit there, behaviour unchanged).
5. **Log redaction**: a logging filter applied to api and worker loggers that redacts emails, phone numbers, TRNs (15 digits), IBANs, bearer tokens and document text fields; logs never include document text or prompts outside dev.
6. **Admin metrics page** (`/admin/metrics`, Admin only) backed by `GET /api/v1/admin/metrics` in `app/metrics`: documents processed, share of fields needing review, correction rate per field, match exception rate, approval cycle time, AI calls/tokens/estimated cost today vs the daily budget, Q&A refusal rate — computed from Postgres.
7. **Errors**: consistent 404/500 pages, an "API unavailable" friendly state when the BFF cannot reach the api (no crash, no stack trace), toast on failed mutations.

## Acceptance
- One upload can be traced by a single request ID across api logs, worker logs and its audit entries (integration test).
- Logs hold no document text, emails or TRNs (unit test on the filter + an integration check of captured logs during an upload/extract).
- Stopping the api container shows a friendly error page in the web app, not a crash.
- Q&A: an S8 answerable question shows the answer with citations that open the right page; an unanswerable one shows the refusal message.
