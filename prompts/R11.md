## Scope
1. `make eval` (`python -m eval.run --mode replay|live --out eval/reports/<timestamp>`): runs the reduced evaluation set through the real pipeline code paths (extraction on the 20 documents, Q&A on the 30 questions, injection on the 15 cases plus enough generated variants to reach ≥ 30 attack documents/questions for AIQ-08, comparison explanations for the S1/S5 comparisons) and computes **every AIQ metric** with target, value and pass/fail, writing `report.json` and `report.md`. Exit non-zero when any metric is below target. `--mode live` uses the live AI provider and refuses to run unless `AI_PROVIDER=live` and an explicit `--confirm-live` flag are given (it costs money; it is run by the reviewer only after gate G1). Live mode prints a token/cost estimate before starting and enforces `--max-cost-usd` (default 0.50).
2. CI: an `eval` job running `make eval` in replay mode (needs Postgres service like the integration job); fails on any drop below target.
3. **Demo-script E2E suite** (Playwright) that follows the spec's 5-minute demo script end to end with the seeded accounts: sign-in per role, S1 upload → review → confirm (three quotes), comparison + recommendation + override reason, PO + approval by manager.it, S3 match → exception → escalate → Manager decision, Q&A with a citation click and a refusal, S7 injection banner, audit viewer + hash-chain verify, Admin cannot approve. Parameterised by `WEB_BASE_URL` (local or hosted) and credentials from env; it must create its own data each run (unique numbers) so it can run repeatedly against the same environment. Must pass **three times in a row** locally (`make e2e-demo` with `--repeat-each` or a loop).
4. `scripts/smoke.sh <base-url>` for the deploy pipeline: `/healthz`, `/readyz` (via web), sign-in page 200, `/api/v1/me` 401 without token, one login with a demo account from env and `/me` 200. Exit codes suitable for CI.

- **Q&A AI metric events (small gap left by R10):** make the Q&A answer path emit the same AI metric event as extraction by calling `app.ai.cost.record_ai_call_metrics(task="qa", ...)` with model, prompt version, latency, tokens, refusal flag and injection flag where Q&A already counts tokens — one minimal call, no behaviour change; add a unit test that the event is emitted for an answered and a refused question.
