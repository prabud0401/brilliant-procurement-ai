## Scope
1. **Purchase requests**: list (scoped) and detail with status timeline and approval steps; create/edit form with lines (product from seeded catalogue, qty, est. price, AED totals live), submit; link confirmed quotation documents.
2. **Comparison**: create for a PR from its confirmed quotes; side-by-side table per item with paired lines, price/delivery/terms/completeness, scores and weights (Buyer can adjust weights within design 6.4 rules), recommended vendor highlighted with the explanation text; manual pairing move; include/exclude quote with reason; **decision dialog** — choosing a vendor other than the recommendation requires an override reason (US-10).
3. **Purchase orders**: create PO from the chosen quote, detail view (lines, VAT, totals), submit for approval, **Push to Odoo** button showing the mock adapter's reference ("Odoo (mock adapter)").
4. **Approvals**: inbox (only steps the user can decide), **one-screen approval** with the facts (request/PO summary, comparison result, documents links, totals, tier, previous steps) and Approve / Reject (reject needs a reason); SoD and limit errors shown from problem details.
5. **Three-way match**: run match for an invoice against its PO; result table per line (ordered/received/invoiced qty, prices, variance AED, status badges); **exception queue** with actions per policy: Buyer accept (≤ AED 500, never over-billed qty, reason required) or escalate; Manager decides escalated ones.
6. **Admin** (Admin role only): Users & roles (list users, grant/revoke roles, set Manager approval limit, activate/deactivate — backend `app/admin` endpoints, audited, Admin cannot grant itself business roles silently: audit entry with reason); Settings (thresholds, tolerances, Buyer policy via the existing settings API, showing version history); **Integrations page** listing each adapter with mode, labelled e.g. "Odoo (mock adapter)" (backend endpoint returning adapter names/modes from `app.integrations`); **Audit viewer** (filters, paging, hash-chain verify button, CSV export) — non-Admin roles see the audit view scoped by the API where design 7.2 allows.
7. **Reference data**: add read-only `GET /api/v1/vendors` and `GET /api/v1/products` (any business role; Admin too) in a new backend module `app/reference` (owned by you), and switch R08's vendor picker (`apps/web/src/lib/constants/vendors.ts`) and your forms to the API; delete the hard-coded vendor constants.
8. Navigation: switch on Requests, Comparisons, Purchase orders, Approvals, Matches, Admin, Audit for the right roles only; no dead links.
