## Bugs (found on the hosted live app)
1. Match line table shows a blank Description and Inv Unit Price **AED 0.00** even when the match is correct (e.g. IT match and the Operations INV-5510 price variance of AED 1,600). `MatchDetail.tsx` reads `line.invoice_unit_price`, `line.description`, and `line.line_no`; the API sends `inv_unit_price` and has no description field. `formatMoneyAED(undefined)` becomes AED 0.00.
2. Exception queue `useState("open")`. After a buyer escalates, the row vanishes for the buyer and for the assigned manager until they manually pick "Escalated to Manager". The Operations manager therefore sees "No exceptions found in this queue."
3. PO line VAT is stored as `0.05` and rendered as `{line.vat_rate}%` → **0.0500%** instead of 5%.

## Scope
1. **Match lines:** In `MatchDetail.tsx`, read `inv_unit_price` (accept either name for safety). Add `description` (and `line_no` if useful) to `MatchLineResponse`, populated from the PO line description (fallback invoice line description). Show that description in the table. Keep money as Decimal/AED helpers.
2. **Exception queue default:** Default the filter so **both open and escalated** rows are visible to buyers and to the escalation manager without changing the filter (e.g. default "Needs action" / unresolved). Extend `GET /exceptions` if it only accepts a single exact status: add `unresolved` (or equivalent) meaning `open` or `escalated`, and use that as the UI default. Keep explicit Open / Escalated / All options. Do not hide manager reject/accept actions on escalated rows; buyers should see escalated rows as already escalated (no need to escalate again).
3. **VAT display:** In `PODetail.tsx` (and any other PO VAT `%` render), if `vat_rate <= 1`, display it as a percentage (0.05 → "5.00%"), not "0.05%". Do not change stored values or tax calculation.
4. Regenerate OpenAPI / `apps/web/src/lib/api/schema.d.ts` the way the repo already does (`npm run gen:api`) if the API schema changes.
5. Docs: one line in `docs/release-notes.md`.
