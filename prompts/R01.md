## Scope
1. Monorepo skeleton: `apps/web/README.md` (one line: Next.js app arrives in R05), `services/backend`, `infra/README.md`, `eval/` and `e2e/` NOT needed now.
2. `services/backend/pyproject.toml` with uv (Python 3.12): fastapi, uvicorn, pydantic-settings, sqlalchemy>=2, alembic, psycopg[binary], pgvector, pyjwt, argon2-cffi (or passlib[argon2]), structlog or std logging JSON; dev: pytest, httpx, ruff, mypy. Commit `uv.lock`.
3. Docker Compose: `db` (pgvector/pgvector:pg16, healthcheck), `azurite` (mcr.microsoft.com/azure-storage/azurite), `api` (uvicorn, port 8000, waits for db healthy, runs `alembic upgrade head` on start via the migrator URL), `worker` (`python -m app.worker_main`: polls the `jobs` table with `FOR UPDATE SKIP LOCKED`, no job handlers yet beyond a no-op `ping` type, logs and exits cleanly on SIGTERM). A `web` service under compose profile `web` pointing at `apps/web` (built later in R05) so `make up` does not need it. Compose reads `.env`; provide sane local defaults so `cp .env.example .env` + local dev values work — add a `make env` target that creates `.env` with random local values (JWT secret via `python -c secrets`, DEMO_USER_PASSWORD random, printed once to the terminal) if `.env` is missing. Never commit `.env`.
4. FastAPI app: `/healthz` (liveness), `/readyz` (DB reachable), versioned router `/api/v1`, request-id middleware (X-Request-ID), problem-json error handler per design 5.2, CORS off by default.
5. Alembic migrations for **every table in design 4.3 and 4.4** (columns, types, FKs, unique and partial unique indexes, `vector(1536)` + HNSW index and GIN tsvector index on `chunks`, CHECK constraints for status enums). Enable `vector` and `pgcrypto` extensions. Two DB roles created by migration: `app_user` (runtime: SELECT/INSERT/UPDATE/DELETE on business tables, but only INSERT/SELECT on `audit_log`) and the migration owner. Migration must downgrade cleanly.
6. Audit log: `audit_log` as design 4.4; `BEFORE UPDATE OR DELETE` (and TRUNCATE) trigger that raises; hash chain `hash = sha256(prev_hash || canonical_json(row fields))` computed in Python inside `audit.record(session, actor, action, entity_type, entity_id, before=None, after=None, reason=None, ai_model=None, prompt_version=None)` using a transaction-level advisory lock to serialise the chain; a `verify_chain()` function. Audit API: `GET /api/v1/audit` (filters + pagination per 5.3; scope: requester own records, buyer all business, manager department, admin all), `GET /api/v1/audit/export.csv` (admin only), `GET /api/v1/audit/verify` (admin), and PUT/PATCH/DELETE on `/audit` return 405.
7. Auth: local password sign-in `POST /api/v1/auth/login` (argon2 hashes), HS256 JWT with sub, roles, dept, exp, iss; `GET /api/v1/me`. Login success/failure writes audit entries (no password in logs). Simple per-IP login rate limit (in-memory is fine).
8. RBAC policy layer in `app/core/policy.py`: a single declarative capability table mirroring design 7.2 (capability -> per-role rule: none / own / dept / all / tier/limit marker) and a FastAPI dependency `require(capability)` returning a `Principal`; helper `scope_filter(principal, capability, model)` for queries. Admin has no business permissions unless also granted a business role. Unknown/invalid/expired/tampered token -> 401.
9. Demo accounts bootstrap `python -m app.core.bootstrap` (idempotent upsert): departments Facilities, IT, Projects; fictional users for each role (at least: 2 requesters in different departments, 2 buyers, manager with approval_limit_aed 50000, manager with 250000, admin), emails `@demo-holdings.example`, `is_demo=true`, password from env `DEMO_USER_PASSWORD` (refuse to run if unset). Writes audit entries.
10. Makefile targets: env, up, down, logs, migrate, seed (runs bootstrap, then `python -m seed.load` only if `seed/load.py` exists), lint, test, test-int, fmt. Root README: a short "Run locally" section.
11. CI `.github/workflows/ci.yml` on pull_request and push to main: jobs `lint` (ruff, mypy), `test` (unit+security), `integration` (service container pgvector/pgvector:pg16, run alembic upgrade/downgrade/upgrade then integration tests), `secrets` (gitleaks via `docker run --rm -v $PWD:/repo zricethezav/gitleaks:latest detect --source /repo --no-git -v` or the gitleaks binary — do not use gitleaks-action, it needs a licence), `build` (docker build of the backend image). Use uv caching. Keep total runtime small.

## Acceptance
- `make env && make up` gives healthy db, azurite, api, worker; `curl localhost:8000/readyz` is 200.
- `make seed` twice is idempotent; each demo role can log in and `GET /api/v1/me` shows its roles.
- As `app_user`, UPDATE/DELETE/TRUNCATE on audit_log fail; hash chain verifies; tampering a row as superuser (trigger disabled in the test) makes `verify_chain()` fail.
- Each role reaches exactly its audit endpoints per design 7.2; other records -> 404/filtered.
- CI workflow file is valid and all jobs would pass.
