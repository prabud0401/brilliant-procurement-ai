## Bugs (seen on the hosted live app, after Document Intelligence + current cleanup)

1. **Currency AEO.** Gulf Line quote Q-1042 PDF says `Currency: AED`. Cleanup already maps "AED"/"Dhs"/"د.إ" in `_CURRENCY_MAP`, but `clean_currency` then accepts *any* 3-letter token and uppercases it, so OCR `AEO` (D/O confusion) is stored as `AEO`.
2. **Payment terms.** Same quote PDF says `Payment Terms: Net 30`; stored value is `net 38`. INV-7001 PDF/generator says `Net 60`; stored value is `Net 68`. Digit OCR confusion (0/8). `clean_header_field` only strips the leading label for `payment_terms`.
3. **Comparison Lead Time is "Not specified"** for Gulf Line, Falcon and Corniche, even though the PDFs include `Delivery Lead Time: N days` (generator: Q-1042 Gulf Line **5 days**, Falcon Q-8821 **7 days**, Corniche **10 days**). Root cause: lead time is not in `KNOWN_HEADER_FIELDS` or the live field guide, so it is never extracted. `get_comparison` already calls `get_doc_lead_time` (names `lead_time_days`, `delivery_lead_time`, `lead_time`, `delivery_time`) — once the field is stored, the matrix will fill on GET with no UI change. The recommendation text that said "7 days" for Gulf Line is wrong; use the document value (5 days for Q-1042). Do not invent 7.

## Scope

Map obvious OCR confusions (`AEO`, `AED` with letter/digit swaps like `AFD` if you have a tight list) to AED when justified. If the code is still unknown: prefer a valid ISO code found in the document / PDF text layer / OCR `source_text` / page content (e.g. `Currency: AED`); if the vendor or document is UAE (TRN, address, or currency-in-text is AED) default to `AED`. Never leave `AEO` in the stored value. Tests: `AEO` → `AED`; `Currency: AED` unchanged; `USD` stays `USD`; `AEO` plus page text `Currency: AED` → `AED`.
