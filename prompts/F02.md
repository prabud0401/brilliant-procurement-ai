## Scope
1. **Extraction structured output**: use Azure OpenAI structured outputs — `response_format={"type": "json_schema", "json_schema": {"name": "extraction_result", "schema": <schema>, "strict": true}}` (gpt-5-mini supports this on 2025-04-01-preview). Build the schema from `ExtractionResult` with a small helper that makes it strict-compatible (inline/resolve `$defs` refs as needed, every object `additionalProperties: false`, every property listed in `required`, optional fields expressed as nullable types, no unsupported keywords such as `default`, `format`, `pattern`, `minimum`, `maxLength` etc.). The model output must still validate with `ExtractionResult.model_validate_json`. If some field type cannot be expressed strictly, use `strict: false` and say why in the report. Also include a short field guide in the system prompt (key names, page number and exact source text per value), keeping the existing injection-defence wording.
2. **Audit every other live AI path for the same gap**: classification (must return exactly one allowed label — normalise/validate the reply, map unknown to `other`), Q&A answer writer (already describes a schema in text — switch to the same strict `json_schema` mechanism with a matching Pydantic/JSON schema), comparison explanation (plain text is fine; make sure it handles empty output and does not need JSON), and anything else under `app/ai/**` or the eval that calls Azure OpenAI. Fix each gap found and list them in the report.
3. **Recording stays compatible**: `--record-replay` fixtures written from structured-output responses must still load in `ReplayLlmClient` (existing round-trip test must still pass; extend it for a json_schema-style response).
4. **Docs**: replace leftover LaTeX (`$\ge$`, `$\le$` and similar) in `README.md`, `docs/*.md` with plain characters (≥, ≤) or words; in `docs/release-notes.md`, US-20 citation deep-links were delivered (Q&A citations open the cited page in the viewer) — move it out of the backlog/known-issues list into delivered features.
