## Scope
1. Purchase requests: create/edit/list/get (scope per 7.2), submit -> routing by tiers with `rule_snapshot`: ≤ AED 5,000.00 Buyer (tier 1); 5,000.01–50,000.00 department Manager within limit; > 50,000.00 two Managers (sequence 1 then 2, second with sufficient limit). Next eligible approver logic; skip creator.
2. Approvals: approval_steps creation, inbox (`GET /approvals/inbox`), decision `POST /approvals/{id}/decision` (approve/reject + comment, reject needs reason). Segregation of duties enforced in three places (step build, inbox listing, decision endpoint -> 403 `SOD_BLOCKED`). Over-limit approval -> 403. Admin without business role cannot approve.
3. Quote comparison: create for a PR from confirmed quotation documents; item pairing (item code, then text similarity via difflib/rapidfuzz, manual move audited); expired quotes need include_reason; deterministic score with fixed default weights 60/20/10/10 (price, delivery, payment terms, completeness) per design 6.4; explanation generated from a facts JSON through the `LlmClient` interface if available — implement a local `ExplanationWriter` protocol with a template implementation as default plus a faithfulness checker (every number in the text must appear in the facts JSON; otherwise replace with the template) — R03 owns `app/ai`, so keep your adapter in `comparison/` and accept an injected callable; decision with override reason (required when choice != recommendation), audited.
4. Purchase orders: from chosen quote; idempotency key; PO approval via same routing; push to Odoo through the `integrations` odoo mock (outbox entry, idempotent).
5. Three-way match per design 6.5: PO vs delivery notes (sum received) vs invoice; tolerance snapshot from settings; line statuses matched/within_tolerance/exception; exceptions for price variance, quantity over-billing (invoiced > received), missing lines. Buyer can accept exceptions only within AED 500 policy and never for over-billed quantity, with reason; others escalate to Manager who decides. All audited.
6. Settings API (admin): GET/PUT thresholds, tolerances, Buyer exception policy, versioned; changes audited with before/after.
