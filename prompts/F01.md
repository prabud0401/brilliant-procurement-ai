## Scope
1. **Live client** (`app/ai/providers/live.py`): API version from a new setting `AZURE_OPENAI_API_VERSION` (default `2025-04-01-preview`); for chat calls send `max_completion_tokens` (classification 512, extraction 16000, Q&A 4000, explanation 4000 — reasoning tokens count here) and `reasoning_effort` from a new setting `AZURE_OPENAI_REASONING_EFFORT` (default `low`), and never send `temperature` or `max_tokens`. Keep `response_format={"type":"json_object"}` where used. Default `AZURE_OPENAI_DEPLOYMENT` becomes `gpt-5-mini`. Respect Document Intelligence F0 limits: at most 1 request per second (simple client-side throttle) and retry on 429 with backoff (max 3 tries). Handle empty/`length`-truncated responses with a clear `ProblemException` instead of a JSON crash.
2. **Pricing** (`app/ai/cost.py`): replace the hard-coded gpt-4o-mini rates with a small per-model price table in USD per 1M tokens (gpt-5-mini 0.25 in / 2.00 out; gpt-5.4-mini 0.75 / 4.50; gpt-4o-mini 0.15 / 0.60; text-embedding-3-small 0.02 in), selected by the deployment/model name, converted to AED at 3.6725; unknown model → the most expensive listed rate (conservative). Reasoning tokens are already inside completion tokens.
3. **Daily AI cap**: default `AI_DAILY_BUDGET_AED` 7.0 in config and `seed/data/settings.json` (and `.env.example` if listed there).
4. **Eval live safety** (`eval/runner.py`, `eval/run.py`): `estimate_live_cost_usd` uses the price table for the configured deployment, with realistic reasoning-token headroom; add a **running cost meter** that sums actual usage of every live call (chat + embeddings; DI F0 = 0) and aborts the run cleanly (report written, non-zero exit) as soon as the actual spend would exceed `--max-cost-usd`. Report the actual USD spend and tokens in the report and on stdout.
5. **Fixture recording**: `--record-replay` (live mode only) writes each live Document Intelligence result and each live extraction chat response to `eval/data/replay/<doc>.di.json` / `<doc>.openai.json` in exactly the format `ReplayDocumentAnalyzer`/`ReplayLlmClient` read today (overwrite), so a later replay run uses real model output. Add a unit test that a recorded fixture round-trips through the replay providers.
6. **Docs**: update `docs/runbook.md` (switching to live: env names only, `AI_PROVIDER=live`, the eval command with `--confirm-live --max-cost-usd 3 --record-replay`) and the model name in `docs/architecture.md`/README where gpt-4o-mini is named as the deployed model (say the chat model is configurable, default gpt-5-mini).
