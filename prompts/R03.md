## Scope
1. Upload `POST /api/v1/documents` (multipart): magic-byte type check (PDF, PNG, JPEG, TIFF), size limit from settings (default 4 MB while DI F0), ≤20 pages, reject encrypted/corrupt PDFs (pypdf structure only), SHA-256 exact-duplicate detection (`duplicate_of`, warning not silent drop), random blob name in a private container (Azurite locally via azure-storage-blob; storage behind a small interface with an in-memory/local-filesystem implementation for tests), audit entry, enqueue `extract` job. List/get/download (`/file` with Content-Disposition + nosniff) with RBAC scope per design 7.2 (others' records -> 404). PATCH doc type/PR/PO link. Per-user upload rate limit.
2. Job queue + worker: `jobs` table, claim with `FOR UPDATE SKIP LOCKED`, retries with exponential backoff, `last_error`, failed status leaves document stored with `failed` status and a retry endpoint `POST /documents/{id}/extract`.
3. `ai` module — the ONLY place that talks to AI: interfaces `DocumentAnalyzer` (DI) and `LlmClient` (chat + embeddings); providers `mock` (deterministic), `replay` (serves `eval/data/replay` fixtures by document sha256/doc id), `live` (Azure SDK clients, configured by env names only; NOT exercised in tests, no network). Token/cost metering into `extractions`, response cache keyed by sha256+prompt_version, daily AI budget from settings (refuse with clear error when exceeded). Default `AI_PROVIDER=replay` for local demo, `mock` for unit tests.
4. Extraction pipeline per design 6.1–6.3: classify doc type, rule-based injection screen (patterns from design 7.5 and the R02 injection cases; on hit set `documents.suspicious`, write `injection_flags` with snippet hash + page, audit `injection.flagged`), strict JSON-schema extraction with document text inside delimiters and an instruction to ignore embedded instructions, evidence spans (page + bbox from DI words), combined confidence (DI × LLM agreement), fields under 0.80 -> `needs_review`. Model output can never set status, approve or change anything except proposed field values.
5. Validation: line arithmetic, subtotal+VAT=total, VAT 5%, TRN 15 digits, dates sane, PO reference exists — failures set `validation_failed` with message.
6. Review endpoints: PATCH fields/lines (correct, audited with before/after), POST confirm (blocked while any field is needs_review/validation_failed or document is suspicious and not acknowledged — 409 with problem json), POST vendor (choose from seeded vendors), POST not-duplicate with reason. Buyer-only per design 7.2.
