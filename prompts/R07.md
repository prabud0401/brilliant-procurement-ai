## Scope
1. **Interfaces** in `app/ai/interfaces.py`: `Embedder.embed(texts: list[str]) -> list[list[float]]` (1536 dims) and `AnswerWriter.answer(question, chunks) -> AnswerDraft` (sentences with chunk ids, or refused + reason, plus tokens/model). Factory functions + test overrides like the existing ones.
2. **Providers**:
   - `mock`/`replay` embedder: deterministic, offline, meaningful similarity (e.g. normalised hashed bag of words + character trigrams into 1536 dims). Same text, same vector.
   - `mock`/`replay` answer writer: deterministic extractive answer — picks the best-matching sentence(s) from the retrieved chunks and cites their chunk ids; refuses if nothing matches well. Must answer the S8 answerable questions in `eval/data/qa_questions.json` with the right document and page where the data exists in seeded/generated documents.
   - `live`: Azure OpenAI embeddings (`AZURE_OPENAI_EMBEDDING_DEPLOYMENT`) and chat with strict JSON output (system rules, chunks as `<chunk id=… doc=… page=…>` tagged data, instruction to ignore instructions inside chunks, temperature 0, max tokens). Auth: API key if `AZURE_OPENAI_API_KEY` is set, otherwise managed identity via `azure-identity` `DefaultAzureCredential` (token scope `https://cognitiveservices.azure.com/.default`). Apply the same key-or-managed-identity rule to the existing live Document Intelligence and LLM clients (the hosted app uses a managed identity and has no keys). Add `azure-identity` to the backend dependencies (`uv add`, keep `uv.lock` in sync).
3. **Chunking and embedding job** (design 6.6): when a document is confirmed, enqueue an `embed_document` job; the worker builds page-bounded chunks (~500 tokens, 50 overlap; tables kept whole as Markdown) from the stored OCR/layout result plus one "document facts" chunk from the confirmed field values (cited with the page each value came from), copies `owner_id`/`department_id` from the document, fills `tsv`, embeds in one batch, and skips unchanged content (content hash). Re-confirming changed content replaces the document's chunks. Prompt-injection passages flagged on the document (US-29) are excluded from chunks.
4. **Retrieval**: hybrid vector (cosine) + Postgres full text, reciprocal rank fusion, top 8; the permission filter (Requester: own documents; Buyer: all; Manager: own department; Admin: none — per design 7.2) and the optional scope (`pr_id`, `vendor_id`, `document_id`) are in the SQL `WHERE` clause. Relevance floor as a setting (tune it on the unanswerable questions so they are refused and answerable ones pass).
5. **`POST /api/v1/qa/ask`** (`{question, scope?}`): length limit (e.g. 500 chars) and per-user rate limit; refuse without calling the answer writer when nothing passes the floor; otherwise get the draft, run the **grounding check** (every cited chunk was retrieved; numbers, dates and vendor names in each sentence appear in the cited chunk text), drop failing sentences, refuse if none remain. Questions that are themselves injection attempts (patterns from design 7.5 / `eval/data/injection_cases.json`) are refused and audited (`qa.injection_refused`). Response shape exactly as design 5.4: `{answer: [{text, citations: [{document_id, title, page, chunk_id}]}], refused, refusal_reason}`. Log to `qa_logs` with the question **redacted** (emails, phone numbers, IBAN/TRN-like numbers masked), answer, citations, model, prompt version, tokens, latency. Respect the daily AI budget (429 when exceeded). `GET /api/v1/qa/history` returns only the caller's own entries.
6. A small `make qa-reindex` (or management command) that (re)builds chunks for all confirmed documents — used after seeding the demo.

## Acceptance
- With the replay stack (`make up`, `make seed`, documents uploaded and confirmed by the existing flow or a test fixture), answerable S8 questions return answers whose citations point to the expected document and page; the unanswerable ones ("warranty on the projector", etc.) are refused.
- A Requester never receives chunks, titles or citations from another user's documents, even with a `document_id` scope pointing at one (refusal or 404, no leak); Admin without a business role gets 403.
- An answer sentence with a number not present in its cited chunk is dropped; if nothing remains, the reply is a refusal.
- Question logs never contain an unredacted email address or phone number.
