## Scope
1. `infra/main.bicep` (resource-group scope) + modules for ONE environment (`env` parameter, default `prod`, region `uaenorth`), names `<type>-pda-<env>-uaen` per design 9.2:
   - Log Analytics + Application Insights (workspace-based)
   - User-assigned managed identity
   - Key Vault (RBAC mode, soft delete on, purge protection OFF so teardown is clean; MI gets Key Vault Secrets User). Secrets are created as **parameters marked `@secure()`** with no defaults (JWT secret, DB passwords, demo user password); never hard-coded.
   - Storage account (no shared key access where possible, TLS 1.2, private `documents` container; MI gets Storage Blob Data Contributor)
   - Postgres Flexible Server, Burstable `Standard_B1ms`, v16, 32 GB, backup 7 days, no HA, `azure.extensions` allow-list `VECTOR,PGCRYPTO`, firewall rule allowing Azure services; admin password from secure param; database `pda`
   - Container Apps environment (Consumption) + three apps: `web` (external ingress, min 0 max 1), `api` (internal ingress, min 0 max 1), `worker` (no ingress, min 0 max 1); secrets referenced from Key Vault via the MI; probes on `/healthz` and `/readyz`; images as parameters (GHCR by default, registry credentials via secure param)
   - A Container Apps **job** `migrate` (manual trigger) that runs `alembic upgrade head` then `python -m app.core.bootstrap` and `python -m seed.load`
   - Tags `project=brilliant-pda`, `env`, `owner=prabudeva`, `expires=2026-11-29`
2. `infra/budget.bicep` (subscription scope): monthly budget USD 20, alerts at 50% and 100% actual (USD 10 and 20) to an email parameter. Deployed first at G1.
3. `infra/ai.bicep` (resource-group scope, used at gate G1 only): Azure OpenAI account (S0) with a chat deployment and an embedding deployment — model names/versions/SKU (`GlobalStandard` vs `Standard`) are parameters, defaults gpt-4o-mini + text-embedding-3-small with small capacity (e.g. 10K TPM); Document Intelligence `FormRecognizer` kind with SKU `F0`; MI gets "Cognitive Services User" so no keys are needed. Outputs endpoints only, never keys.
4. `infra/README.md`: what each file creates, the exact gate order (G1: budget → ai.bicep; G2: main.bicep), the expected resource list per gate (must match sprint plan 9.1), and the one-command deploy and teardown.
5. `scripts/teardown.sh <env>`: deletes the resource group(s) (`rg-pda-<env>-uaen`, `rg-pda-ai-uaen`), purges the soft-deleted Key Vault and Cognitive Services accounts so nothing lingers, and lists anything still tagged `project=brilliant-pda` afterwards. Requires a typed confirmation unless `--yes`. `scripts/deploy.sh` for a manual deploy (whatif first, then create) — written, not run.
6. `.github/workflows/deploy.yml`: triggered by `v*` tags and `workflow_dispatch`; uses GitHub environment `prod` (manual approval configured in GitHub later); OIDC `azure/login` (client/tenant/subscription IDs from environment variables/secrets, no client secret); builds and pushes api/worker and web images to GHCR with the commit SHA tag; `az deployment group what-if` then `create` with secure params from GitHub secrets; starts the `migrate` job and waits; smoke test (`/healthz` through the web app's public URL and `/api/v1/me` 401 without a token). Plus a `teardown` workflow_dispatch job that runs `scripts/teardown.sh prod --yes` with approval.
7. CI `bicep` job: `az bicep build` for every `.bicep` file and `az bicep lint` with warnings reviewed; plus `shellcheck` on `scripts/*.sh`.
