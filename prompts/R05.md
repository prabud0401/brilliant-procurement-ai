## Scope
1. Next.js (App Router, latest stable), TypeScript strict, Tailwind, pnpm or npm with a committed lockfile, Node 22+. ESLint + `tsc --noEmit` + Vitest for unit tests. Production `Dockerfile` (multi-stage, standalone output, non-root user) and the compose `web` service enabled by default (remove the `web` profile) on port 3000, talking to the api via `API_BASE_URL=http://api:8000` (server side only).
2. Backend-for-frontend: Route Handlers under `app/api/**` proxy to the FastAPI api. The JWT is stored only in an httpOnly, Secure (except on plain-http localhost dev), SameSite=Lax cookie; it is never returned to or readable by browser JavaScript. Sign-in route posts credentials to the api, sets the cookie; sign-out clears it; a generic proxy handler forwards GET/POST/PATCH/PUT/DELETE to `/api/v1/*` with the bearer token and the `X-Request-ID`, passing problem+json errors through. CSRF protection for state-changing requests (double-submit token or Origin/Host check — document which). Security headers via `next.config`/middleware: CSP, HSTS (prod), `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'`.
3. Typed API client generated from the api's OpenAPI (`openapi-typescript`), with an npm script `gen:api` that reads `http://localhost:8000/openapi.json` (or a committed `openapi.json` snapshot — commit the snapshot so builds don't need the api).
4. Sign-in page (email + password, error states, demo accounts labelled "Demo" — list the demo emails, never passwords), signed-in layout with header (user name, role badges, department, sign out), role-aware navigation driven by one config: each item has the roles that may see it and an `enabled` flag; **only finished features are shown** — for now that is the Home page only (later runs switch on Documents, Requests, Comparisons, Approvals, Matches, Q&A, Admin, Audit). No dead links, no "coming soon".
5. Home page per role: welcome, what this role can do in the app (short text per role from spec section 2), and the user's details from `/me`. Middleware redirects unauthenticated users to sign-in; expired/invalid token → sign-in with a message.
6. Shared components for later runs: data table (sorting, pagination, empty state), form fields with validation messages, status badges, confidence badge, toast notifications, loading skeleton, empty state, error state (renders problem+json title/detail and request id), confirm dialog. Accessible (labels, focus, keyboard), Gulf Standard Time date formatting helper and AED money formatter.
7. Error pages: `not-found`, `error` (no stack traces), friendly message when the api is unreachable.

## Acceptance
- The token is never readable from browser JavaScript (`document.cookie` does not contain it; no token in any JSON response to the browser).
- Each role sees only its menu items; no dead links.
- `docker compose up` serves the web app at http://localhost:3000 and sign-in works for every demo account.
